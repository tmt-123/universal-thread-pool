# 性能基准

构建和运行命令见根目录 README。默认参数为 1000 个元素、4 个工作线程、3 轮。可指定范围为 1～10000 个元素、1～64 个工作线程、1～100 轮。

## 测量内容

| case | 工作内容 |
| --- | --- |
| `submit_future` | 逐个提交返回 i+1 的任务，再逐个读取 future 并求和 |
| `bulk_submit` | 批量提交相同任务，再读取 future 并求和 |
| `parallel_for` | guided 分块填充数组，再对数组求和 |
| `std_async` | 每个元素使用 `std::async(std::launch::async, ...)`，再读取 future 并求和 |

所有路径使用相同元素数，期望校验和为 N*(N+1)/2。校验失败返回非零退出码。线程池使用默认指标采集、固定线程数、每批8个任务，测量前提交一个空任务并等待空闲；线程池创建和销毁不计入区间。每轮按表格顺序执行，不随机打乱。

计时包含容器分配、任务提交或分块调度、等待结果及求和；校验和检查与打印不计入区间。CSV 的 `total_ns` 为整段工作耗时，`ns_per_op` 为总耗时除以元素数，不是单个任务排队或执行延迟。并行循环使用分块，实际提交的内部任务数与元素数不同。`std::async` 不复用本项目线程池，其并发方式也不受线程池线程数参数控制。

## 运行记录

`sample-results.csv` 保存本次实际运行的原始输出，`environment.txt` 保存对应环境和命令。它是轻量任务在该机器上的单次运行记录，不用于推导真实业务吞吐或跨机器性能。对比时保持任务数、线程数、编译选项和机器负载一致，保留每轮数据；发生系统线程资源不足时应降低任务数并重新记录完整命令。
